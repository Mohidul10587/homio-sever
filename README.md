## Tile SaaS API

Multi-tenant NestJS API for tile-shop vendors. Tenant identity is always read from the JWT; no vendor-scoped endpoint accepts a client-provided `vendorId`.

Implemented modules include vendor authentication, brands, categories, suppliers and supplier ledgers, customers and customer ledgers, products, purchase orders and idempotent goods receiving, POS sales, inventory ledger/adjustments, vendor dashboard, and super-admin vendor management/dashboard.

## Configuration and database

Copy `.env.example` to `.env`, set a real PostgreSQL URL and JWT secret, then create/update the local schema:

```bash
npx prisma db push
npx prisma generate
```

The current schema intentionally contains no `ProductVariant` model: every product is an independently stockable, sellable tile item.

## Public vendor storefronts

Each vendor receives a unique, URL-safe slug when their account is registered. Their public storefront and filterable catalogue are available at:

```text
/store/<vendor-slug>
/store/<vendor-slug>/tiles
```

The public API only returns active products, their selling prices, images, brands, and categories. It never exposes workspace, inventory, cost-price, or customer data.

After pulling this change, add the `slug` column and assign slugs to vendors that already exist:

```bash
npx prisma db push
npx prisma generate
npm run backfill:vendor-slugs
```

## Image storage (MinIO)

Product images are stored in your MinIO server. Set the `MINIO_*` values in `.env`; `MINIO_ENDPOINT` is the host name only (without `http://`), while `MINIO_PUBLIC_URL` is the browser-accessible MinIO API URL. The API creates `MINIO_BUCKET` automatically if it does not exist.

Allow anonymous **download** access for that bucket so browsers can display the returned `imageUrl`; keep write access private and only use the server credentials in this API. Upload an image as multipart form data to:

```text
POST /api/products/:id/image
Authorization: Bearer <token>
Content-Type: multipart/form-data
field name: image
```

JPEG, PNG, and WebP images up to 5 MB are accepted. Objects are stored under a vendor-specific path, and replacing an image removes the old MinIO object when it belongs to this bucket.

## Deployment

When you're ready to deploy your NestJS application to production, there are some key steps you can take to ensure it runs as efficiently as possible. Check out the [deployment documentation](https://docs.nestjs.com/deployment) for more information.

If you are looking for a cloud-based platform to deploy your NestJS application, check out [Mau](https://mau.nestjs.com), our official platform for deploying NestJS applications on AWS. Mau makes deployment straightforward and fast, requiring just a few simple steps:

```bash
$ npm install -g @nestjs/mau
$ mau deploy
```

With Mau, you can deploy your application in just a few clicks, allowing you to focus on building features rather than managing infrastructure.
